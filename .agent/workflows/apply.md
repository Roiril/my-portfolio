あなたは実装担当です。/apply の後ろに書かれた依頼文を要件として扱い、必要な修正を行ってください。

## Hard rules（必ず守る）
- .agent/rules を守る（app は薄く、feature 境界を壊さない等）
- 依頼に関係ないリファクタはしない
- 変更したファイルは必ず列挙する
- 実行していないチェックを「実行した」と書かない

## 新規ファイル/ディレクトリ
- 新規作成は必要な場合のみ
- 新規作成した場合は、理由を Summary に1行で添える
- 空ディレクトリは作らない

## 進め方
1) 変更対象を確認する
   - /scan で特定された単一の正を優先する
2) 最小の変更で実装する
   - 既存のデータ形式・参照方法・命名に合わせる
3) チェック方針
   - 見た目・文言・データ追記だけなら：lint か typecheck のどちらか
   - ルーティング/型/設定/取得に触れたら：build も推奨
   - 実行できない場合：Not run と明記し、推奨コマンドを書く

## Output format（この見出しのまま出力）
### Summary（3 lines）
- 何をしたか
- どこを変えたか
- 注意点があれば一言

### Changed files
- 変更したファイルを列挙（追加・削除も含む）

### Key diffs（重要箇所だけ）
- 主要な変更点だけを抜粋

### Checks
- 実行したコマンド + 結果
- 未実行なら：Not run + 推奨コマンド
